# 部署说明

## 新实例

1. 在项目根目录运行 `python3 scripts/init_env.py`，随机生成互不相同的数据库/root/管理员密码和签名密钥。不会覆盖现有 `.env`。
2. 仅空数据库初始化时在 `deploy/.env` 设置 `DDL_AUTO=update`。
3. `cd deploy && docker compose up -d --build`。
4. 检查日志、确认建表成功，立即将 `DDL_AUTO=validate`，运行 `docker compose up -d --force-recreate backend`。
5. 打开 `http://127.0.0.1:8080`。只有通过可信 HTTPS 才允许发送真实公网凭据。

目前没有经过验证的 Flyway 基线。`update` 仅提供新空库的初始建表便捷方式，不是生产迁移方案。

## HTTPS

Compose 只把后端绑定到 `127.0.0.1:8080`，MySQL 无主机端口。将 `deploy/nginx.conf` 按实际域名、证书路径调整并包含于宿主 Nginx 的 `http {}` 中。配置文件内有 `limit_req_zone`，不能嵌套于 `server {}`。先运行 `nginx -t`，再由运维重载。

Nginx 示例覆盖 Forwarded/X-Forwarded-*，对登录和注册限流。确认所有入口均通过该可信代理后，设置 `FORWARD_HEADERS_STRATEGY=framework` 并重建后端容器，才能记录客户端真实 IP；否则保留默认 none，记录代理地址而非相信伪造头。

不支持匿名 WebSocket。头像业务限制 200KB，预设 2MB；Spring 单文件限制 2MB、总 multipart 3MB，Nginx 总请求 3MB。

## 维护

- 备份 MySQL 数据卷，定期验证恢复；不得把备份上传源码仓库。
- `.env` 仅服务器账号可读。Android 共享存储可能不支持 POSIX 0600，生产请使用 Linux 私有目录或专用秘密管理系统。
- 日志不得记录密码、Authorization、请求体、完整设备信息或聊天内容。
- 更新镜像时先在数据库副本验证；回滚代码不等于可以回滚数据库。
- 已有线上实例必须按 MIGRATION.md 审核变更，不能仅替换 JAR 并假定兼容。
